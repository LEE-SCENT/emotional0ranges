# 상세 페이지 템플릿

어드민에서 블록을 골라 쌓아 상세 페이지를 조립합니다. 여기는 그 **재료**만 둡니다 —
제품 화면(`../detail.html`)에는 붙이지 않았습니다.

```
templete/
  index.html   블록 카탈로그. 블록마다 desktop 750 · mobile 390 을 나란히 놓았습니다.
  samples.html 조립 예. 블록 두셋을 붙인 짧은 조합들 (Figma Sample 과 같은)
  page.html    상세 페이지. 블록 24개로 조립한 한 판 (티키타카 로테이션 소개팅)
  blocks.css   블록 스타일 전부
  blocks.js    아코디언 접기·펴기, 사진 한 장짜리 캐러셀 정리
  icons.svg    제품 스프라이트에 없는 아이콘만 (plus · minus · download)
  icons/       그 셋의 Figma 원본
  images/      블록 예시에 쓰는 이미지 (클로저 로펌 로고 · 지도 그림 — 모두 Figma 원본)
```

카탈로그에는 값을 바꿔 보는 작은 조작판이 둘 있습니다 — Image Solid 의 배경색 선택기와
Location 의 네이버 키 칸. **블록의 일부가 아닙니다.** `blocks.css` 에는 없고, 어드민이
만들 화면을 대신 흉내 낼 뿐입니다.

`npm run preview` 뒤 세 쪽에서 확인합니다. 위쪽 탭으로 오갑니다.

| 쪽 | 무엇 |
| --- | --- |
| [블록](index.html) | 블록 하나하나. 기기별·상태별로 나란히 |
| [조립 예](samples.html) | 블록 두셋을 붙인 짧은 조합 (Figma Sample 과 같은) |
| [상세 페이지](page.html) | 블록 24개로 조립한 한 판 |

셋을 나눈 것은 보는 목적이 다르기 때문입니다 — "이 블록이 어떻게 생겼나", "둘을 붙이면
어떻게 되나", "한 판이 되면 어떻게 읽히나". 한 쪽에 섞어 두면 서로를 가립니다.

상세 페이지에는 타이틀 · 본문 · 목록 · 이미지 · 캐러셀 · 지도 · 버튼 · 쿠폰 · 아코디언이
모두 들어 있고, 블록 사이에 따로 넣은 여백은 없습니다. 데스크톱과 모바일이 같은 내용을 받아
폰트 · 여백 · 배치만 달라지는 것도 그 한 판에서 나란히 보입니다.

원본: Figma `상세페이지 템플릿` 섹션 (`75:91609`).

## 쓰는 법

```html
<link rel="stylesheet" href="../build/tokens.css">
<link rel="stylesheet" href="../components/tag.css">          <!-- Carousel Products 만 -->
<link rel="stylesheet" href="../components/product-card.css"> <!-- Carousel Products 만 -->
<link rel="stylesheet" href="./blocks.css">

<div class="tpl tpl--desktop">
  <section class="tpl-block tpl-title"> … </section>
  <section class="tpl-block tpl-text">  … </section>
</div>
```

```js
import { initTemplete } from './blocks.js'

initTemplete()                                        // 아코디언 · 캐러셀
initTemplete(document, { naver: { clientId: '…' } })  // 지도까지
```

블록은 그냥 쌓기만 합니다. 블록 사이 여백을 따로 두지 않는 것은 각 블록이 이미 자기
위아래 여백을 들고 있기 때문입니다 — 어드민이 순서를 바꿔도 간격이 흐트러지지 않습니다.

다만 **글 블록이 연달아 서면 여백이 두 겹으로 쌓입니다** — 앞의 아래 60 과 뒤의 위 40 이
더해져 100 이 됩니다. 01·02·03 이 이어지는 자리에는 너무 멀어, 이어지는 글 블록의 위 여백을
걷어 60 으로 둡니다.

```css
:is(.tpl-text, .tpl-list) + :is(.tpl-text, .tpl-list) { padding-block-start: 0; }
```

⚠️ Figma 는 블록을 하나씩만 놓고 여백을 정했습니다. **쌓았을 때의 간격은 시안에 없어 여기서
   정했습니다** — 다른 값이 맞으면 그 한 줄만 고치면 됩니다.

### 더 벌리고 싶을 때 — Spacer

섹션을 끊는 자리에는 `.tpl-spacer` 를 넣습니다. 크기는 셋뿐입니다.

```html
<div class="tpl-block tpl-spacer tpl-spacer--s"></div>   <!-- 데스크톱  40 · 모바일 24 -->
<div class="tpl-block tpl-spacer"></div>                 <!-- 데스크톱  80 · 모바일 40 -->
<div class="tpl-block tpl-spacer tpl-spacer--l"></div>   <!-- 데스크톱 120 · 모바일 60 -->
```

**블록마다 여백을 값으로 열지 않은 이유가 있습니다.** 어드민 화면에는 "얼마나 띄울지" 판단할
근거가 없어, 한 사람은 40 을 다른 사람은 80 을 넣습니다 — 같은 상품의 상세 페이지가 회차마다
달라집니다. 스페이서는 운영이 **"여기서 끊는다"는 뜻을 고르는 것**이고, 얼마나 띄울지는
템플릿이 정합니다. 자유 입력을 두면 결국 값을 여는 것과 같아지므로 크기도 셋으로 막았습니다.

앞뒤 블록이 이미 가진 여백에 더해집니다 — 글 블록이 이어지는 자리라면 60 위에 얹혀
100 · 140 · 180 이 됩니다. 스페이서를 사이에 끼워도 위의 겹침 정리는 그대로 작동합니다.

⚠️ Figma 에 없는 블록이고, 크기 세 값도 여기서 정했습니다.

## 기기는 밖에서 정합니다

`.tpl--desktop` / `.tpl--mobile` 을 렌더러가 붙입니다. 미디어 쿼리로 자동 전환하지
않습니다.

데스크톱 기준 폭이 750, PC 상세 콘텐츠 영역은 최대 852 입니다. **둘 다 흔한 모바일
브레이크포인트(960)보다 좁아서, 콘텐츠 영역의 폭만 보고는 어느 쪽인지 알 수 없습니다.**
Figma 의 `device` variant 와 같은 방식으로 밖에서 정해 넣습니다. 어드민 미리보기가
데스크톱과 모바일을 한 화면에 나란히 띄우는 것도 이 방식이라야 됩니다.

콘텐츠는 PC·모바일 공통으로 한 번만 등록합니다. 블록 순서와 내용은 그대로 두고
폰트·여백·배치만 바뀝니다 — 그래서 기기 차이를 `blocks.css` 맨 위 커스텀 프로퍼티
한 벌로 모아두고, 블록 규칙은 한 번만 씁니다.

## 값의 출처

색·여백·아이콘 크기는 `../build/tokens.css` 의 semantic 토큰입니다. **디자인 토큰은
정의된 내용을 그대로 따릅니다** — 여기서 새로 만들지 않습니다.

글자만 다릅니다. 템플릿 전용 텍스트 스타일 여덟 개가 `semantic/typography/template` 에
새로 들어갔습니다.

| 토큰 | 크기 / 행간 | 굵기 | 쓰는 곳 |
| --- | --- | --- | --- |
| `template/title-l` `title-l-mobile` | 52 / 130% · 28 / 130% | semibold | Title 의 타이틀 |
| `template/title-s` `title-s-mobile` | 28 / 130% · 16 / 150% | semibold | Text·List 의 머리, 아코디언 질문 |
| `template/label` `label-mobile` | 20 / 140% · 14 / 140% | semibold | Title 의 라벨, 버튼·쿠폰 문구 |
| `template/text` `text-mobile` | 24 / 140% · 14 / 140% | regular | 본문, 목록 항목, 아코디언 답변 |

> **⚠️ 템플릿 토큰은 템플릿에서만 씁니다.** 제품 화면은 `body/*` `heading/*` 을 쓰세요.
> `--typography-template-*` 이 `templete/` 밖에서 보이면 잘못 쓴 것입니다.
>
> ```sh
> grep -rn "typography-template" --include="*.css" --include="*.html" . | grep -v "^./templete/" | grep -v "^./build/"
> ```

`title-l-mobile` 과 `title-s` 는 값이 같습니다(28 / 130%). 하나로 합치지 않은 것은 둘이
서로 다른 결정이어서입니다 — 넓은 화면의 소제목이 24 로 바뀌어도 좁은 화면의 대제목은
28 에 남아야 합니다.

`title-s-mobile` 만 행간이 130 이 아니라 150 입니다. 좁은 화면에서 소제목이 본문 크기
(16)까지 내려오면, 타이틀처럼 붙여 짜는 대신 읽기 좋게 벌립니다.

## 블록

### 콘텐츠 블록

| 블록 | 클래스 | 어드민이 넣는 것 |
| --- | --- | --- |
| Title | `.tpl-title` | 라벨(옵션) · 타이틀(최대 2줄) |
| Text | `.tpl-text` | 타이틀(옵션) · 본문 문단 · 번호(옵션) · 메타(옵션) · 별점(옵션) |
| List | `.tpl-list` | 타이틀(옵션) · 글머리 기호 목록 |
| Spacer | `.tpl-spacer` | 섹션을 끊는 빈 블록. 크기 셋 중 선택 |

Text 블록의 **머리는 통째로 생략할 수 있고, 머리가 있으면 타이틀은 필수**입니다.
번호·메타·별점은 각각 선택이며, 데스크톱 전용이 아닙니다 — 모바일에서도 같이 씁니다.
글자는 그 기기의 머리 글꼴을 그대로 따르고 별 크기만 다릅니다(데스크톱 28 · 모바일 20 —
⚠️ 모바일 별 크기는 시안이 없어 정한 값입니다).

메타와 별점 앞의 점은 **구분자라서 CSS 가 놓습니다**(`::before`, 4px, #A6A4A3). 메타의
내용이 아니므로 마크업에 적지 마세요 — 손으로 넣게 두면 메타만 끈 날 점 두 개가 나란히
남습니다. 무엇을 켜고 끄든 개수와 자리는 저절로 맞습니다. 번호에는 점을 두지 않습니다:
타이틀 앞에 붙는 순번이지 나란히 선 항목이 아닙니다.

같은 텍스트 데이터를 PC·모바일이 함께 씁니다. 이미지처럼 비율로 줄이지 않고 기기별
타이포그래피를 적용하며, 컨테이너 폭에 따라 줄바꿈과 높이가 늘어납니다.

**타이틀 블록의 타이틀은 최대 2줄입니다.** 그 수를 넘는 글은 **어드민이 입력 단계에서
경고해 막는 것이 먼저**이고, 코드의 자르기는 그래도 넘어온 글이 뒤 블록을 밀어내지 않게
하는 그물입니다 — 둘 중 하나만 두면 안 됩니다. 자르기만 두면 운영은 글이 사라진 줄
모르고, 경고만 두면 어느 경로로든 새어 들어온 긴 글이 판을 무너뜨립니다.

줄 수는 밖에서 바꿀 수 있습니다:

```html
<section class="tpl-block tpl-title" style="--tpl-title-lines: 3">
```

⚠️ **라벨은 자르지 않습니다.** 가이드가 "타이틀과 라벨"이라고 적었지만 라벨의 최대 줄 수는
   시안에 없습니다. 없는 수를 짐작해 잘라 두면 운영이 넣은 글이 소리 없이 사라집니다 —
   수가 정해지면 타이틀처럼 한 줄만 더하면 됩니다. 그때까지는 어드민의 입력 경고가 유일한
   방어선입니다.

### 이미지 블록

| 블록 | 클래스 | 규칙 |
| --- | --- | --- |
| Image Full | `.tpl-image-full` | 컨테이너 100%, 높이는 원본 비율. 750×480 → PC 852×545 · 모바일 350×224 |
| Image Solid | `.tpl-image-solid` | 단색 배경은 코드가 만들고 그 위에 이미지·로고만. 배경색은 이미지에 맞춰 Hex 지정 |
| Carousel Images | `.tpl-carousel-images` | **최소 3장** · 최대 10장 권장. 이미지 + 대체 텍스트. PC 2개 · 모바일 1개와 다음 것 일부 |

PC·모바일이 같은 이미지를 씁니다. 가로만 늘리거나 찌그러뜨리지 않고, 화면 너비에 따라
바뀌는 것은 카드 폭과 노출 개수뿐입니다. 권장 해상도는 블록마다 다릅니다 — Image Full ·
Image Solid 는 **가로 1704px 이상**(PC 852 의 2배), Carousel Images 는 **가로 1000px
이상**입니다. 캐러셀은 카드가 한 판을 다 쓰지 않아 그만큼 여유가 있습니다.

캐러셀 이미지는 **대체 텍스트도 구성 항목**입니다. 어드민이 이미지마다 함께 등록하고
`alt` 로 들어갑니다 — 사진이 오지 않아도, 화면을 읽어 주는 쪽에서도 무엇이 있었는지는
남습니다.

사진이 한 장뿐이면 `blocks.js` 가 캐러셀을 걷어내고 Full Image 처럼 보여줍니다 — 넘길
것이 없는데 반쯤 잘린 여백만 남지 않게 합니다.

Image Solid 의 **배경색과 문구색은 둘 다 Hex 로 지정**합니다. 어드민 값이
`style="--tpl-solid-bg:#151D34; --tpl-solid-fg:#A8978D"` 로 들어오고, 지정하지 않으면
`#151D34` · `#A8978D`(casualNeutral/200) 입니다.

⚠️ 배경색은 올리는 이미지가 정하고 문구색은 그 배경 위에서 읽혀야 하는데, 둘 다 어드민
   값이라 대비가 무너질 수 있습니다 — 어두운 배경에 어두운 문구를 넣어도 코드가 막아주지
   않습니다. **입력 단계에서 대비를 확인**하세요.
안쪽 이미지는 **fit**(`object-fit: contain`)입니다 — 자리 안에 전부 들어오게 맞추고
잘라내지 않습니다. 로고나 일러스트는 한쪽 귀퉁이가 잘리면 다른 물건이 됩니다.

### 데이터 연동

| 블록 | 클래스 | 연동 |
| --- | --- | --- |
| Carousel Products | `.tpl-carousel-products` | **최소 3개**. 상품만 고르면 이름·사진·가격·일정·잔여석은 상품 데이터가 채웁니다 |
| Location | `.tpl-location` | 위도·경도(핀 하나). **지도 한 장이 블록 전부입니다** |

상품 카드는 디자인 시스템의 `.product-card` 를 그대로 씁니다 — 어드민이 카드 안을
이미지처럼 직접 편집하지 않습니다. 최소 3장이 규칙이고, 노출 종료·판매 중지 상품은 자동
제외되며, 하나만 남으면 넘기는 UI 를 숨기고, 하나도 없으면 블록 전체를 숨깁니다.

**줄의 바깥 모서리만 둥급니다** — 첫 카드의 왼쪽 위아래, 마지막 카드의 오른쪽 위아래에
`rounded/l`(12). 가운데 카드들은 각지게 두어야 여러 장이 한 덩어리로 읽힙니다. DOM
순서에 고정되므로 스크롤해도 움직이지 않습니다 — 보이는 위치를 따라가게 하면 줄 한가운데에
둥근 모서리가 떠 보입니다. 디자인 시스템의 `.product-card-group` 이 같은 규칙을 이미
갖고 있어 그 토큰을 그대로 씁니다.

**좌우 여백(데스크톱 48 · 모바일 24)은 스크롤이 끝에 닿았을 때만 보입니다.** 미는 동안에는
카드가 그 자리를 지나 블록 가장자리까지 갑니다. 여백은 블록이 아니라 스크롤 칸이 자기
안쪽에 갖습니다(`padding-inline` + `scroll-padding-inline`) — 블록에 주면 카드가 늘 48
안쪽에서 잘려 넘기는 내내 옆에 빈 띠가 서고, 음수 margin 으로 넓히면 카드가 블록 밖으로
삐져나옵니다.

지도는 등록된 좌표에 핀 하나입니다. 높이는 PC 360 · 모바일 240 이고 폭만 컨테이너를
따릅니다. 주소가 바뀌면 좌표를 다시 검색·저장해야 합니다 — 지도는 좌표만 보고 그립니다.

**장소명·주소·안내는 Location 블록이 들고 있지 않습니다.** 바로 아래 Text 블록의
머리(타이틀 · 메타)와 본문으로 적고, 바깥 지도 링크는 Button 블록입니다 — Figma Sample
이 그 조합입니다:

```
Location  지도
Text      주차 정보 · 서울 용산구 한남오거리 라운지
          건물 지하 주차장을 2시간 무료로 …
Button    네이버 지도에서 보기  >
```

**지도가 오지 않으면** — 키가 없거나, 스크립트가 막혔거나, 좌표가 비었거나 — 자리는
그대로 두고 `지도를 불러오지 못했습니다` 한 줄만 남깁니다.

```html
<section class="tpl-block tpl-location" data-lat="…" data-lng="…" data-label="…">
  <p class="tpl-location__fallback">지도를 불러오지 못했습니다</p>
</section>
```

장소명·주소·안내를 여기에 다시 적지 않습니다. 그것들은 이미 아래 Text 블록에, 바깥 지도
링크는 Button 블록에 있습니다 — 같은 주소가 두 번 서고 "네이버 지도에서 보기"가 두 개가
되면 운영은 어느 쪽을 고쳐야 하는지 알 수 없습니다. 정책의 "지도 로딩 실패 시 장소명·주소와
외부 지도 링크는 유지"는 **그 블록들이 제자리에 있는 것으로 이미 지켜집니다** — Location 이
죽어도 그것들은 죽지 않습니다.

⚠️ 그래서 **Location 은 Text · Button 과 함께 쓰는 것이 기본**입니다. 지도만 단독으로
   놓으면 실패했을 때 장소를 알 길이 없습니다. 그때는 `.tpl-location__link` 로 링크
   하나를 넣으세요(스타일은 남겨 두었습니다).

대체 글은 **스크립트가 만들지 않고 마크업에 미리 적어 둡니다.** 지도가 그려지면
`is-mapped` 가 붙어 지도 뒤로 숨습니다. 반대로 두면(빈 자리를 스크립트가 채우는 식)
정작 스크립트가 죽은 날 빈 회색 상자만 남아, 지도가 있었는지조차 알 수 없습니다.

지도가 뜨든 안 뜨든 자리의 크기는 같습니다. 실패했다고 블록이 접히면 그 아래 글들이 위로
올라와 읽던 자리를 잃습니다.

조립 예([samples.html](samples.html))의 Location 에는 **시안의 지도 그림**을 넣어
`is-mapped` 를 붙여 두었습니다. 위쪽 칸에 키를 넣고 그리면 진짜 지도가 그 위를 덮고 그림은
치워집니다. 키는 이 브라우저에만 기억되고 저장소에는 남지 않습니다.

지도는 **네이버 지도 JS API** 로 그립니다. 좌표는 마크업에, 키는 부르는 쪽에 둡니다 —
어드민·제품·이 카탈로그가 서로 다른 키를 쓰고, 무엇보다 키가 저장소에 남지 않아야 합니다.

```html
<section class="tpl-block tpl-location"
         data-lat="37.5385" data-lng="127.0027" data-label="한남오거리 라운지"></section>
```

```js
import { initLocation } from './blocks.js'
initLocation(document, { clientId: 'YOUR_KEY' })
```

`src` 를 넘기면 주소를 그대로 씁니다(`clientId`·`param` 은 무시). 키 파라미터 이름이
다르거나, 서브모듈이 필요하거나(`&submodules=geocoder`), 사내 프록시를 거칠 때 씁니다.

⚠️ 키는 네이버 클라우드 플랫폼에서 발급받고, **그 키의 Web 서비스 URL 에 지도를 띄울
   주소가 등록돼 있어야 합니다** — 카탈로그에서 시험한다면 `http://localhost:4321`.
   등록되지 않은 곳에서는 인증 오류로 지도가 뜨지 않습니다.

⚠️ 넣을 수 있는 것은 **키** 또는 **`oapi.map.naver.com` 의 `maps.js` 주소**뿐입니다.
   지도 *페이지* 주소(`map.naver.com/p/…`)는 다른 것입니다 — 그 주소가 갈 자리는 대체
   글의 "네이버 지도에서 보기" 링크와 Button 블록의 `href` 입니다.

⚠️ 스크립트 주소의 키 파라미터 이름이 발급 시점에 따라 다릅니다 — 새 콘솔에서 받은 키는
`ncpKeyId`, 예전 키는 `ncpClientId` 입니다. 기본값은 `ncpKeyId` 이고, 다르면
`param` 을 바꾸거나 `src` 에 전체 주소를 넣으세요. 키가 없거나 스크립트가 오지 않으면
자리만 비운 채 조용히 넘어갑니다 — 지도 하나 때문에 페이지가 멈출 이유가 없습니다.

카탈로그의 Location 은 상태 둘을 나란히 놓았습니다 — **지도가 있을 때**(시안의 지도 그림에
`is-mapped` 를 손으로 붙였습니다)와 **오지 않았을 때**(대체 글). 키를 넣고 그리면 뒤쪽이
진짜 지도로 바뀝니다.

지도 위에서 휠은 막아 두었습니다. 읽어 내려가는 글 한가운데 놓이는 지도라, 스크롤이
지도에 잡히면 페이지 대신 지도가 확대됩니다. 길찾기는 아래 Button 블록이 네이버 지도로
넘깁니다.

### 액션 블록

| 블록 | 클래스 | 규칙 |
| --- | --- | --- |
| Button | `.tpl-button` | 문구와 연결 동작(내부·외부·지도, 새창 여부)만. 높이·스타일 커스텀 불가 |
| Coupon | `.tpl-coupon` | 쿠폰만 고르면 쿠폰명·할인율·발급 기간·사용 조건은 쿠폰 데이터가 채웁니다 |

버튼이 받는 것은 **버튼명 · 링크(내부 페이지 · 외부 링크 · 지도) · 새창 여부** 셋입니다.
뒤에 붙는 화살표는 24 입니다(글자 20보다 조금 크게).
높이와 스타일은 커스텀할 수 없고, 링크가 없는 버튼은 저장도 노출도 되지 않습니다 —
`[aria-disabled="true"]` 모양은 미리보기에서 그 상태가 보이게 하려는 그물일 뿐입니다.

쿠폰은 눌러서 발급받습니다. 더 이상 받을 수 없으면 `.tpl-coupon--closed` 로 바뀝니다 —
**이미 받았거나(받기 완료), 발급 기간이 끝났거나 다 소진되었거나(발급 종료).** 둘은 모습이
같고 오른쪽 글만 다르므로 상태 클래스는 하나입니다. 다만 발급 종료에는 체크 표시를 넣지
않습니다 — 받은 적이 없는데 체크가 서 있으면 받았다는 뜻이 됩니다.

로그인하지 않은 사용자는 로그인 뒤 원래 화면으로 돌아오고, 상품에 적용할 수 없는 쿠폰은
노출하지 않으며, 받을 수 있는 쿠폰이 없으면 블록 전체를 숨깁니다. PC·모바일이 같은 정보를
쓰고 폭만 반응형입니다.

### 아코디언

`.tpl-accordion` — 질문 하나가 블록 하나입니다. 여러 개를 이어 붙이면 목록이 되고,
칸을 나누는 것은 아래 선 하나입니다. 열린 질문은 브랜드색이 되고 `+` 가 `−` 로
바뀝니다.

아이콘은 회전이 아니라 두 개를 넣고 하나만 보입니다 — `+` 를 돌려 `−` 를 만들면 획
굵기가 방향마다 달라 보입니다.

## Figma 와 다른 곳

1. **폴더 이름이 `templete` 입니다.** Figma 텍스트 스타일 폴더의 철자가 그렇습니다
   (`template` 의 오타). 코드에서는 토큰 이름만 `template` 로 바로잡았고, 디렉터리
   이름은 사용자가 지정한 대로 `templete` 로 두었습니다. Figma 쪽도 고치면 양쪽이
   맞습니다.

2. **버튼·쿠폰 높이를 68 에서 줄였습니다** — 확인된 결정입니다. 데스크톱 56 · 모바일 48
   이고, `--tpl-action-height` 한 값이 둘을 함께 정합니다. 68 은 이 크기의 글자에 견주어
   너무 높았습니다. 다시 조정하려면 `blocks.css` 기기별 값에서 그 한 줄만 고치세요 —
   버튼의 테두리와 쿠폰의 두 칸이 함께 따라옵니다.

3. **쿠폰의 이음매는 파낸 구멍이 아닙니다.** 모서리 8 짜리 사각형 두 개가 사이 없이 그냥
   맞붙어 있고, 이음매에 보이는 흰 자국은 두 모서리 곡선이 만나 생긴 것입니다(Figma
   좌표: Warpper 654×68, logo 68×68 x=0, button 586 x=68 — 간격 0). 반원을 직접 그리면
   위아래로 삐져나와 전혀 다른 물건이 됩니다. 로고 칸은 정사각이라 높이가 바뀌면 폭도
   따라갑니다.

4. **`.btn` 을 쓰지 않았습니다.** 디자인 시스템의 버튼은 32 / 40 / 48 세 크기뿐이고
   높이를 고정하지 않는 규칙이라, 높이를 정해야 하는 이 버튼과 맞지 않습니다. 색은
   `button/outlined` 와 같은 자리를 가리키는 semantic 토큰(`bg` · `border` · `fg`)을
   직접 씁니다.

5. **Image Solid 의 하단 문구만 medium 굵기입니다.** `templete/*` 여덟 개 중 어느
   것과도 맞지 않습니다. 크기·행간이 `templete/text` 와 같아 그 토큰을 쓰고 굵기만
   따로 지정했습니다. 텍스트 스타일로 올릴지 정해야 합니다.

6. **CouponSoldout 의 20% 투명도는 넣지 않습니다** — 확인된 결정입니다. Figma 프레임
   전체에 `opacity: 0.2` 가 걸려 있지만 그대로 두면 "받기 완료"를 읽을 수 없습니다
   (명도 대비가 한참 못 미칩니다). 시안의 흐림은 프레임을 죽여 둔 것이지 상태의
   생김새가 아닙니다. 배경·글자색(`bg-disabled` · `fg-lowest` · `fg-low`)만 옮겼고,
   그것만으로 "이미 받았다"가 충분히 읽힙니다. Figma 쪽 `opacity` 도 걷어내면 양쪽이
   맞습니다.

   로고 심볼만은 브랜드색을 지킵니다 — 바탕은 함께 죽지만 심볼까지 회색이 되면 누구의
   쿠폰이었는지가 지워집니다. 다 쓴 쿠폰도 우리 쿠폰입니다.

7. **모바일 시안이 없는 블록이 셋 있습니다** — Button · Coupon · Image Solid. 데스크톱
   값을 같은 비율로 줄여 넣었고 `blocks.css` 에 ⚠️ 로 표시해 두었습니다.

8. **`plus` · `minus` · `download` 아이콘이 제품 스프라이트에 없습니다.** Figma 에서
   내려받아 `templete/icons.svg` 에 따로 두었습니다(36×36, `currentColor`). 제품
   아이콘 세트를 건드리지 않으려는 것입니다 — 다른 화면에서도 쓰이면 그때
   `icons/figma-export/` 로 옮기세요.
